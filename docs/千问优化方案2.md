## 1. 需求背景与约束

### 1.1 业务背景

光纤网络运维系统中，每条网元间连纤（Inter-NE Fiber）需要根据其宿端链路的告警状态实时计算健康颜色：

| 颜色     | 含义     | 触发条件                       |
| -------- | -------- | ------------------------------ |
| 🔴 RED    | 业务中断 | 宿端关键链路存在 CRITICAL 告警 |
| 🟡 YELLOW | 业务劣化 | 宿端链路存在 MINOR 告警        |
| 🟢 GREEN  | 业务正常 | 无告警或保护倒换成功           |

### 1.2 颜色判定场景

```
场景1：宿端为有源盘（Active Board）
  └── 直接检查宿端 Port-1 告警

场景2：宿端为无源盘（Passive Board）
  ├── Case A：Port-2 和 Port-3 均有网元内连纤（双路保护）
  ├── Case B：仅 Port-2 有网元内连纤（单路）
  └── Case C：Port-2/3 均无网元内连纤（无保护路径）
```

### 1.3 核心需求约束

| 编号  | 约束                                         | 设计影响                 |
| ----- | -------------------------------------------- | ------------------------ |
| R-15  | 颜色仅基于宿端判断                           | 寻路只关注宿端链路       |
| R-23  | 情况A单侧紧急=绿色（有意设计）               | 短路规则的业务依据       |
| R-24  | 颜色判定通过告警缓存完成，不实时调RPC        | 计算必须纯内存           |
| R-25  | 告警消息先更新缓存再触发重算                 | 处理顺序不可变           |
| R-26  | 同一(board_id, port_id, alarm_level)只存一条 | 存在性模型，非计数器     |
| R-27  | 存在即激活，不存在即无告警                   | 布尔语义                 |
| R-28  | 同端口允许不同alarm_level共存                | 缓存Key必须含alarm_level |
| NF-14 | 颜色重算延迟 ≤ 3s                            | 端到端延迟上限           |
| NF-17 | 告警缓存与AlarmService最终一致               | 不可丢弃任何告警         |
| Q25   | 单侧紧急=绿色是有意设计                      | 短路逻辑正确性基础       |

### 1.4 场景2 Case A 完整决策表

| B (Port-2有源盘) | A2 (Port-3有源盘) | 颜色     | 说明               |
| ---------------- | ----------------- | -------- | ------------------ |
| CRITICAL         | CRITICAL          | 🔴 RED    | 双路中断           |
| CRITICAL         | MINOR             | 🟡 YELLOW | 主路中断+备路劣化  |
| CRITICAL         | 无告警            | 🟢 GREEN  | R-23: 保护倒换成功 |
| MINOR            | CRITICAL          | 🟡 YELLOW | 主路劣化+备路中断  |
| MINOR            | MINOR             | 🟡 YELLOW | 双路劣化           |
| MINOR            | 无告警            | 🟡 YELLOW | 主路劣化           |
| 无告警           | CRITICAL          | 🟢 GREEN  | R-23: 保护倒换成功 |
| 无告警           | MINOR             | 🟡 YELLOW | 备路劣化           |
| 无告警           | 无告警            | 🟢 GREEN  | 正常               |

## 2. 现有系统问题分析

### 2.1 正确性问题（P0）

| 编号  | 问题                                                         | 严重度 | 位置                                                  |
| ----- | ------------------------------------------------------------ | ------ | ----------------------------------------------------- |
| BUG-1 | `full_color_recalc()` 中 `std::mutex` 不可重入导致死锁       | 致命   | `calculate_color()` 内部二次加锁 `fiber_cache_mutex_` |
| BUG-2 | ABBA 死锁：`GetColoredFibers()` 先锁 `color_cache_mutex_` 再锁 `fiber_cache_mutex_`，其他路径相反 | 致命   | 多处                                                  |
| BUG-3 | `GetFiberStatsRealtime()` 跨锁访问 `fiber_by_id_` 和 `alarm_cache_` | 高     | 数据竞争                                              |
| BUG-4 | `subscribe_fiber_events()` 断线后不重连                      | 高     | 拓扑事件丢失                                          |
| BUG-5 | `init_alarm_sync_async` 使用 detached thread，析构时悬空指针 | 中     | 生命周期管理                                          |

### 2.2 性能问题（P1）

| 编号   | 问题                                       | 影响                |
| ------ | ------------------------------------------ | ------------------- |
| PERF-1 | 告警到达后 O(n) 遍历所有连纤寻找受影响者   | 千级连纤时 3~6ms/条 |
| PERF-2 | 颜色计算中同步 DB 写入阻塞事件处理         | 10~50ms/次          |
| PERF-3 | 无闪断抑制，设备抖动导致颜色频繁翻转       | 无效DB写入+推送风暴 |
| PERF-4 | 无短路预判，颜色不可能变化时仍执行完整计算 | 浪费CPU             |

### 2.3 可维护性问题（P2）

| 编号    | 问题                                        | 影响                   |
| ------- | ------------------------------------------- | ---------------------- |
| MAINT-1 | 颜色计算逻辑硬编码在 `calculate_color()` 中 | 新增场景需修改核心函数 |
| MAINT-2 | 依赖构建逻辑与场景判断耦合                  | 违反开闭原则           |
| MAINT-3 | 6个 gRPC 接口中"查找 active board"逻辑重复  | 修改需改6处            |
| MAINT-4 | SQL 拼接存在注入风险                        | 安全隐患               |

## 3. 设计原则与目标

### 3.1 设计原则

| 原则             | 说明                                       |
| ---------------- | ------------------------------------------ |
| **正确性优先**   | 严格对齐 R-24~R-28，不丢弃任何告警事件     |
| **单线程消费**   | 所有事件串行处理，从根本上消除竞态和死锁   |
| **事件自包含**   | FIBER_CREATED 携带完整信息，消除处理时 RPC |
| **策略可扩展**   | 新增场景只需新增策略类，核心引擎零修改     |
| **依赖自声明**   | 策略声明自己依赖哪些端口，构建器通用化     |
| **计算与IO解耦** | 颜色计算纯内存，DB/推送异步批量            |
| **渐进式实施**   | 分阶段交付，每阶段可独立验证和回滚         |

### 3.2 性能目标

| 指标                        | 当前       | 目标              |
| --------------------------- | ---------- | ----------------- |
| 单条告警处理延迟            | 3~6ms      | < 0.1ms（纯内存） |
| 端到端延迟（告警→颜色更新） | 15~60ms    | < 5ms             |
| 寻路复杂度                  | O(n)       | O(1)              |
| 吞吐能力                    | ~200 条/秒 | > 10,000 条/秒    |
| 闪断场景无效计算            | 100%       | < 5%（合并后）    |
| 死锁风险                    | 存在       | 消除              |

## 5. 线程模型

### 5.1 线程清单

| 线程                  | 数量     | 职责                             | 生命周期                     |
| --------------------- | -------- | -------------------------------- | ---------------------------- |
| gRPC Server 线程池    | gRPC管理 | 处理 RPC 请求（GetFiberColor等） | 服务全生命周期               |
| alarm_stream_thread_  | 1        | 订阅告警事件流，写入合并队列     | 服务全生命周期，断线自动重连 |
| fiber_stream_thread_  | 1        | 订阅拓扑事件流，写入有序队列     | 服务全生命周期，断线自动重连 |
| event_process_thread_ | 1        | 串行消费所有事件，计算颜色       | 服务全生命周期               |
| output_thread_        | 1        | 批量DB写入 + 颜色事件推送        | 服务全生命周期               |
| timer_thread_         | 1        | 趋势采集 + 数据清理              | 服务全生命周期               |

**总计：6个自管理线程 + gRPC线程池**

### 5.2 线程间通信

```
alarm_stream_thread_ ──┐
                       ├──→ CoalescingEventQueue ──→ event_process_thread_
fiber_stream_thread_ ──┘                                    │
                                                            │ change_queue (SPSC)
                                                            ▼
                                                     output_thread_

timer_thread_ ──→ DB（独立，无共享状态）
```

### 5.3 同步机制

| 通信路径              | 机制                                     | 说明                 |
| --------------------- | ---------------------------------------- | -------------------- |
| Stream → EventQueue   | `std::mutex` + `std::condition_variable` | 有界队列，满时阻塞   |
| EventQueue → 处理线程 | `std::condition_variable` 等待           | 超时100ms轮询        |
| 处理线程 → 输出线程   | SPSC 无锁环形队列                        | 单生产者单消费者     |
| 处理线程内部          | **无锁**（单线程）                       | 所有缓存仅该线程访问 |

### 5.4 关键设计：单线程消费消除竞态

```
┌─────────────────────────────────────────────────────────────┐
│  event_process_thread_ 独占访问：                            │
│                                                              │
│  · alarm_cache_          （告警缓存）                        │
│  · fiber_by_id_          （连纤缓存）                        │
│  · fiber_by_port_        （端口反查索引）                    │
│  · port_dependency_index_（端口依赖索引）                    │
│  · color_contexts_       （颜色上下文）                      │
│                                                              │
│  → 无需任何 mutex，无死锁可能，无数据竞争                    │
└─────────────────────────────────────────────────────────────┘
```

## 6. 核心数据结构

### 6.1 告警缓存

```cpp
// ═══ 告警缓存 Key ═══
// 约束 R-26: 同一 (board_id, port_id, alarm_level) 只存一条
// 约束 R-28: 同端口允许不同 alarm_level 共存
struct AlarmCacheKey {
    int32_t board_id;
    int8_t  port_id;
    int8_t  alarm_level;   // CRITICAL=1, MINOR=2

    bool operator==(const AlarmCacheKey& o) const {
        return board_id == o.board_id 
            && port_id == o.port_id 
            && alarm_level == o.alarm_level;
    }
};

struct AlarmCacheKeyHash {
    size_t operator()(const AlarmCacheKey& k) const {
        size_t h = std::hash<int32_t>{}(k.board_id);
        h ^= std::hash<int8_t>{}(k.port_id) + 0x9e3779b9 + (h << 6) + (h >> 2);
        h ^= std::hash<int8_t>{}(k.alarm_level) + 0x9e3779b9 + (h << 6) + (h >> 2);
        return h;
    }
};

// ═══ 告警缓存 Value ═══
// 约束 R-27: 存在即激活，不存在即无告警
struct AlarmCacheValue {
    int64_t raised_at_ms;   // 告警产生时间戳
};

// 缓存本体
std::unordered_map<AlarmCacheKey, AlarmCacheValue, AlarmCacheKeyHash> alarm_cache_;
```

### 6.2 连纤缓存

```cpp
// ═══ 板卡类型 ═══
enum class BoardType : int8_t {
    ACTIVE  = 1,   // 有源盘（如 OTU、线路板）
    PASSIVE = 2,   // 无源盘（如 OMU、ODU）
};

// ═══ 连纤缓存条目 ═══
struct FiberCacheEntry {
    int32_t fiber_id;
    
    // 源端
    int32_t src_board_id;
    int8_t  src_port_id;
    
    // 宿端
    int32_t dst_board_id;
    int8_t  dst_port_id;
    
    // 类型
    bool is_inter_ne;          // true=网元间, false=网元内
    
    // 板卡类型（缓存，避免重复查询）
    BoardType src_board_type;
    BoardType dst_board_type;
    
    // 网元信息
    int32_t src_ne_id;
    int32_t dst_ne_id;
};

// 主索引：fiber_id → 连纤信息
std::unordered_map<int32_t, FiberCacheEntry> fiber_by_id_;

// 反查索引：(board_id, port_id) → fiber_id 列表
struct PortKey {
    int32_t board_id;
    int8_t  port_id;
    bool operator==(const PortKey& o) const {
        return board_id == o.board_id && port_id == o.port_id;
    }
};
struct PortKeyHash {
    size_t operator()(const PortKey& k) const {
        return std::hash<int32_t>{}(k.board_id) ^ (std::hash<int8_t>{}(k.port_id) << 16);
    }
};
std::unordered_multimap<PortKey, int32_t, PortKeyHash> fiber_by_port_;
```

### 6.3 端口依赖索引

```cpp
// ═══ 依赖索引 Key ═══
// 注意：不含 alarm_level，任何级别变化都触发重算
// 因为颜色计算需要同时检查 CRITICAL 和 MINOR
struct PortKey {
    int32_t board_id;
    int8_t  port_id;
    // hash + operator== (同上)
};

// ═══ 依赖索引 Value ═══
struct DependencyEntry {
    int32_t fiber_id;   // 受影响的网元间连纤
    int8_t  role;       // 该端口在策略中的角色（策略自定义）
};

// 角色常量（由各策略定义，此处仅为示例）
```

## 7. 事件接收与合并层

### 7.1 设计目标

| 目标           | 实现方式                                           |
| -------------- | -------------------------------------------------- |
| 告警闪断合并   | 同 (board_id, port_id, alarm_level) 仅保留最新一条 |
| 连纤事件保序   | 严格 FIFO，不合并                                  |
| 不丢弃任何事件 | 有界队列，满时阻塞生产者（背压）                   |
| 低延迟唤醒     | condition_variable 通知                            |

### 7.2 CoalescingEventQueue 实现

```cpp
class CoalescingEventQueue {
public:
    struct EventBatch {
        std::vector<AlarmEvent> alarms;   // 已合并，每个key仅最新一条
        std::vector<FiberEvent> fibers;   // 有序，未合并
    };

private:
    // ═══ 告警合并区 ═══
    // Key: (board_id, port_id, alarm_level)
    // Value: 最新的告警事件
    std::unordered_map<AlarmCacheKey, AlarmEvent, AlarmCacheKeyHash> alarm_pending_;
    mutable std::mutex alarm_mutex_;
    
    // ═══ 连纤有序队列 ═══
    std::queue<FiberEvent> fiber_queue_;
    mutable std::mutex fiber_mutex_;
    
    // ═══ 通知机制 ═══
    std::mutex notify_mutex_;
    std::condition_variable notify_cv_;
    std::atomic<bool> has_data_{false};
    
    // ═══ 容量限制 ═══
    static constexpr size_t MAX_ALARM_PENDING = 10000;  // 最多10000个不同key
    static constexpr size_t MAX_FIBER_QUEUE   = 1000;   // 最多1000条连纤事件

public:
    // ═══ 生产者接口（Stream 回调线程调用）═══
    
    void push_alarm(const AlarmEvent& event) {
        AlarmCacheKey key{event.board_id(), event.port_id(), event.alarm_level()};
        {
            std::lock_guard<std::mutex> lock(alarm_mutex_);
            // 背压：超过容量时等待（不丢弃）
            // 实际场景中不太可能触发（10000个不同端口同时告警）
            alarm_pending_[key] = event;  // 覆盖式写入，保留最新
        }
        signal();
    }
    
    void push_fiber(const FiberEvent& event) {
        {
            std::lock_guard<std::mutex> lock(fiber_mutex_);
            fiber_queue_.push(event);
        }
        signal();
    }
    
    // ═══ 消费者接口（事件处理线程调用）═══
    
    EventBatch drain() {
        EventBatch batch;
        
        // 取出所有合并后的告警事件
        {
            std::lock_guard<std::mutex> lock(alarm_mutex_);
            batch.alarms.reserve(alarm_pending_.size());
            for (auto& [key, event] : alarm_pending_) {
                batch.alarms.push_back(std::move(event));
            }
            alarm_pending_.clear();
        }
        
        // 取出所有连纤事件（保序）
        {
            std::lock_guard<std::mutex> lock(fiber_mutex_);
            batch.fibers.reserve(fiber_queue_.size());
            while (!fiber_queue_.empty()) {
                batch.fibers.push_back(std::move(fiber_queue_.front()));
                fiber_queue_.pop();
            }
        }
        
        has_data_.store(false, std::memory_order_release);
        return batch;
    }
    
    // 等待数据到达（超时返回false）
    bool wait_for_data(int timeout_ms = 100) {
        if (has_data_.load(std::memory_order_acquire)) return true;
        std::unique_lock<std::mutex> lock(notify_mutex_);
        return notify_cv_.wait_for(lock, std::chrono::milliseconds(timeout_ms),
            [this]{ return has_data_.load(std::memory_order_acquire); });
    }

private:
    void signal() {
        has_data_.store(true, std::memory_order_release);
        notify_cv_.notify_one();
    }
};
```

### 7.3 合并语义说明

```
时间线示例（同一 board=101, port=1, level=CRITICAL）：

  t=0ms:  RAISED  → alarm_pending_[{101,1,CRIT}] = RAISED(t=0)
  t=2ms:  CLEARED → alarm_pending_[{101,1,CRIT}] = CLEARED(t=2)   [覆盖]
  t=5ms:  RAISED  → alarm_pending_[{101,1,CRIT}] = RAISED(t=5)    [覆盖]
  t=8ms:  CLEARED → alarm_pending_[{101,1,CRIT}] = CLEARED(t=8)   [覆盖]
  
  t=10ms: 消费线程 drain()
          → 取出 CLEARED(t=8)（最终状态）
          → 告警缓存 erase({101,1,CRIT})
          → 颜色重算（如果该端口有关联连纤）

效果：4次翻转 → 1次处理（75%减少）
```

### 7.4 不同 Key 不合并

```
  t=0ms: RAISED {101, 1, CRITICAL}  → 独立条目
  t=1ms: RAISED {101, 1, MINOR}     → 独立条目（不同 alarm_level）
  t=2ms: RAISED {102, 1, CRITICAL}  → 独立条目（不同 board_id）
  
  drain() 后取出 3 条事件（互不影响）
```

### 7.5 连纤事件不合并

```
  t=0ms: FIBER_CREATED  fiber_id=1001  → 入队
  t=1ms: FIBER_DELETED  fiber_id=1001  → 入队（不合并！）
  t=2ms: FIBER_CREATED  fiber_id=1002  → 入队
  
  drain() 后按序取出 3 条（CREATED→DELETED→CREATED 顺序不可变）
```

### 8.1 主循环

```cpp
void FiberMaintServiceImpl::event_processing_loop() {
    LOG_INFO("Event processing thread started");
    
    while (running_.load(std::memory_order_acquire)) {
        // 等待数据（超时100ms，保证退出响应）
        event_queue_.wait_for_data(100);
        
        // 批量取出
        auto batch = event_queue_.drain();
        
        if (batch.fibers.empty() && batch.alarms.empty()) {
            continue;
        }
        
        // ═══ 处理顺序：先连纤，后告警 ═══
        // 原因：连纤变更影响依赖索引，必须先更新索引再处理告警
        
        // Phase 1: 处理连纤事件（更新拓扑缓存 + 依赖索引）
        for (const auto& fiber_event : batch.fibers) {
            handle_fiber_event(fiber_event);
        }
        
        // Phase 2: 处理告警事件（更新告警缓存 + 触发颜色重算）
        for (const auto& alarm_event : batch.alarms) {
            handle_alarm_event(alarm_event);
        }
    }
    
    LOG_INFO("Event processing thread stopped");
}
```

### 8.2 告警事件处理

```cpp
void FiberMaintServiceImpl::handle_alarm_event(const AlarmEvent& event) {
    AlarmCacheKey cache_key{event.board_id(), event.port_id(), event.alarm_level()};
    
    // ═══ Step 1: 更新告警缓存（R-25: 先更新缓存）═══
    if (event.type() == ALARM_RAISED) {
        alarm_cache_[cache_key] = {event.timestamp_ms()};
    } else {  // ALARM_CLEARED
        alarm_cache_.erase(cache_key);
    }
    
    // ═══ Step 2: 查找受影响的连纤（O(1)）═══
    PortKey port_key{event.board_id(), event.port_id()};
    auto it = port_dependency_index_.find(port_key);
    if (it == port_dependency_index_.end()) {
        return;  // 该端口不影响任何网元间连纤
    }
    
    // ═══ Step 3: 逐条重算颜色 ═══
    for (const auto& dep : it->second) {
        recalculate_fiber_color(dep.fiber_id, dep.role, event);
    }
}
```

### 8.3 颜色重算

```cpp
void FiberMaintServiceImpl::recalculate_fiber_color(
    int32_t fiber_id, int8_t role, const AlarmEvent& trigger_event) 
{
    auto ctx_it = color_contexts_.find(fiber_id);
    if (ctx_it == color_contexts_.end()) return;
    
    auto& ctx = ctx_it->second;
    const auto& fiber = fiber_by_id_.at(fiber_id);
    
    // ═══ Step 1: 获取当前策略 ═══
    auto* strategy = scenario_registry_.match(fiber, topo_view_);
    if (!strategy) return;
    
    // ═══ Step 2: 短路预判 ═══
    if (strategy->can_skip(ctx, trigger_event)) {
        return;  // 颜色不可能变化
    }
    
    // ═══ Step 3: 计算新颜色（纯内存，R-24）═══
    FiberColor new_color = strategy->evaluate(ctx, alarm_cache_);
    
    // ═══ Step 4: 比较新旧颜色 ═══
    if (new_color == ctx.current_color) {
        return;  // 未变化，不产生输出
    }
    
    // ═══ Step 5: 颜色变化 → 推入输出队列 ═══
    FiberColor old_color = ctx.current_color;
    ctx.current_color = new_color;
    ctx.last_change_ms = current_time_ms();
    
    change_queue_.push(ColorChangeRecord{
        .fiber_id = fiber_id,
        .old_color = old_color,
        .new_color = new_color,
        .scene_type = strategy->scene_type(),
        .scenario_case = strategy->scenario_case(),
        .timestamp_ms = ctx.last_change_ms,
    });
    
    LOG_INFO("Fiber {} color changed: {} → {}", 
             fiber_id, color_name(old_color), color_name(new_color));
}
```

```cpp
void FiberMaintServiceImpl::handle_fiber_event(const FiberEvent& event) {
    switch (event.type()) {
    case FIBER_CREATED:

        break;
    case FIBER_DELETED:

        break;
    }

void FiberMaintServiceImpl::handle_fiber_created(const FiberEvent& event) {
    // ═══ 直接使用事件中的完整信息（无需RPC）═══
    const auto& info = event.fiber_info();
    
    FiberCacheEntry entry;
    entry.fiber_id      = info.fiber_id();
    entry.src_board_id  = info.src_board_id();
    entry.src_port_id   = info.src_port_id();
    entry.dst_board_id  = info.dst_board_id();
    entry.dst_port_id   = info.dst_port_id();
    entry.is_inter_ne   = info.is_inter_ne();
    entry.src_board_type = static_cast<BoardType>(info.src_board_type());
    entry.dst_board_type = static_cast<BoardType>(info.dst_board_type());
    entry.src_ne_id     = info.src_ne_id();
    entry.dst_ne_id     = info.dst_ne_id();
    
    // 更新连纤缓存
    fiber_by_id_[entry.fiber_id] = entry;
    fiber_by_port_.insert({{entry.src_board_id, entry.src_port_id}, entry.fiber_id});
    fiber_by_port_.insert({{entry.dst_board_id, entry.dst_port_id}, entry.fiber_id});
    
    if (entry.is_inter_ne) {
        // ═══ 网元间连纤：构建依赖 + 初始化颜色 ═══
        dependency_builder_.build(entry);
        init_color_context(entry);
        recalculate_fiber_color(entry.fiber_id, 0, AlarmEvent{});
    } else {
        // ═══ 网元内连纤：检查是否触发场景变更 ═══
        handle_intra_ne_fiber_created(entry);
    }
}

void FiberMaintServiceImpl::handle_fiber_deleted(const FiberEvent& event) {
    int32_t fiber_id = event.fiber_id();
    
    auto it = fiber_by_id_.find(fiber_id);
    if (it == fiber_by_id_.end()) return;
    
    const auto& entry = it->second;
    
    if (entry.is_inter_ne) {
        // ═══ 网元间连纤删除：移除依赖 + 清除颜色 ═══
        dependency_builder_.remove(fiber_id);
        color_contexts_.erase(fiber_id);
    } else {
        // ═══ 网元内连纤删除：先处理场景变更，再删除缓存 ═══
        // 注意：此时缓存中还有该连纤，可以先读取关联信息
        handle_intra_ne_fiber_deleted(entry);
    }
    
    // 从缓存中删除
    fiber_by_port_.erase({entry.src_board_id, entry.src_port_id});
    fiber_by_port_.erase({entry.dst_board_id, entry.dst_port_id});
    fiber_by_id_.erase(fiber_id);
}
```

```cpp
struct PortDependency {

struct PortAlarmSummary {
    bool has_critical = false;
    bool has_minor    = false;
};

// ═══ 告警缓存查询接口 ═══
using AlarmCache = std::unordered_map<AlarmCacheKey, AlarmCacheValue, AlarmCacheKeyHash>;

inline PortAlarmSummary query_port_alarm(const AlarmCache& cache, 
                                          int32_t board_id, int8_t port_id) {
    PortAlarmSummary summary;
    summary.has_critical = cache.count({board_id, port_id, ALARM_CRITICAL}) > 0;
    summary.has_minor    = cache.count({board_id, port_id, ALARM_MINOR}) > 0;
    return summary;
}

// ═══ 拓扑查询视图（只读）═══
class FiberTopologyView {
    const std::unordered_map<int32_t, FiberCacheEntry>& fiber_by_id_;
    const std::unordered_multimap<PortKey, int32_t, PortKeyHash>& fiber_by_port_;
    
public:
    BoardType get_board_type(int32_t board_id) const;
    
    bool has_fiber_on_port(int32_t board_id, int8_t port_id) const {
        return fiber_by_port_.count({board_id, port_id}) > 0;
    }
    
    // 获取某板卡某端口通过网元内连纤连接的对端板卡
    std::optional<int32_t> get_intra_ne_peer_board(int32_t board_id, int8_t port_id) const {
        auto range = fiber_by_port_.equal_range({board_id, port_id});
        for (auto it = range.first; it != range.second; ++it) {
            const auto& fiber = fiber_by_id_.at(it->second);
            if (!fiber.is_inter_ne) {
                return (fiber.src_board_id == board_id) 
                    ? fiber.dst_board_id : fiber.src_board_id;
            }
        }
        return std::nullopt;
    }
};
```

```cpp
        }
        return false;
    }

    int8_t scenario_case() const override { return 0; }
```

### 10.1 通用依赖构建器

```cpp
// ═══ 通用依赖构建器 ═══
// 不包含任何场景逻辑，仅做注册/注销
// 所有场景判断由策略的 declare_dependencies() 完成
class DependencyBuilder {
    std::unordered_map<PortKey, std::vector<DependencyEntry>, PortKeyHash>& index_;
    const ScenarioRegistry& registry_;
    const FiberTopologyView& topo_;
    
public:
    DependencyBuilder(
        std::unordered_map<PortKey, std::vector<DependencyEntry>, PortKeyHash>& index,
        const ScenarioRegistry& registry,
        const FiberTopologyView& topo)
        : index_(index), registry_(registry), topo_(topo) {}
    
    // ─── 构建依赖（通用，零硬编码）───
    void build(const FiberCacheEntry& fiber) {
        const auto* strategy = registry_.match(fiber, topo_);
        if (!strategy) {
            LOG_WARN("No strategy matched for fiber {}", fiber.fiber_id);
            return;
        }
        
        auto deps = strategy->declare_dependencies(fiber, topo_);
        for (const auto& dep : deps) {
            PortKey key{dep.board_id, dep.port_id};
            index_[key].push_back({fiber.fiber_id, dep.role});
        }
        
        LOG_DEBUG("Built {} dependencies for fiber {} (strategy={})", 
                  deps.size(), fiber.fiber_id, strategy->name());
    }
    
    // ─── 移除依赖 ───
    void remove(int32_t fiber_id) {
        for (auto it = index_.begin(); it != index_.end(); ) {
            auto& entries = it->second;
            entries.erase(
                std::remove_if(entries.begin(), entries.end(),
                    [fiber_id](const DependencyEntry& e) { 
                        return e.fiber_id == fiber_id; 
                    }),
                entries.end());
            if (entries.empty()) {
                it = index_.erase(it);
            } else {
                ++it;
            }
        }
    }
    
    // ─── 重建依赖（场景变更时调用）───
    void rebuild(const FiberCacheEntry& fiber) {
        remove(fiber.fiber_id);
        build(fiber);
    }
    
    // ─── 全量构建（服务启动时）───
    void build_all(const std::unordered_map<int32_t, FiberCacheEntry>& fibers) {
        index_.clear();
        for (const auto& [id, fiber] : fibers) {
            if (fiber.is_inter_ne) {
                build(fiber);
            }
        }
        LOG_INFO("Dependency index built: {} port keys, {} fibers",
                 index_.size(), fibers.size());
    }
};
```

### 12.1 SPSC 无锁队列

```cpp
// ═══ 单生产者单消费者无锁环形队列 ═══
template<typename T, size_t Capacity = 4096>
class SPSCQueue {
    alignas(64) std::atomic<size_t> write_pos_{0};
    alignas(64) std::atomic<size_t> read_pos_{0};
    std::array<T, Capacity> buffer_;
    
public:
    bool push(const T& item) {
        size_t wp = write_pos_.load(std::memory_order_relaxed);
        size_t next = (wp + 1) % Capacity;
        if (next == read_pos_.load(std::memory_order_acquire)) {
            return false;  // 队列满
        }
        buffer_[wp] = item;
        write_pos_.store(next, std::memory_order_release);
        return true;
    }
    
    bool pop(T& item) {
        size_t rp = read_pos_.load(std::memory_order_relaxed);
        if (rp == write_pos_.load(std::memory_order_acquire)) {
            return false;  // 队列空
        }
        item = buffer_[rp];
        read_pos_.store((rp + 1) % Capacity, std::memory_order_release);
        return true;
    }
};
```

```cpp
void FiberMaintServiceImpl::output_worker_loop() {
    LOG_INFO("Output worker thread started");
    
    std::vector<ColorChangeRecord> batch;
    batch.reserve(64);
    
    while (running_.load(std::memory_order_acquire)) {
        // 等待数据（超时100ms）
        std::this_thread::sleep_for(std::chrono::milliseconds(10));
        
        // 收集批量
        ColorChangeRecord record;
        while (batch.size() < 20 && change_queue_.pop(record)) {
            batch.push_back(record);
        }
        
        if (batch.empty()) continue;
        
        // 等待凑批（最多再等100ms）
        auto deadline = std::chrono::steady_clock::now() + std::chrono::milliseconds(100);
        while (batch.size() < 20 && std::chrono::steady_clock::now() < deadline) {
            if (change_queue_.pop(record)) {
                batch.push_back(record);
            } else {
                std::this_thread::sleep_for(std::chrono::milliseconds(5));
            }
        }
        
        // ═══ 同 fiber 去重：保留最终状态 ═══
        deduplicate_batch(batch);
        
        // ═══ 批量 DB 写入 ═══
        batch_upsert_fiber_colors(batch);
        batch_insert_color_changes(batch);
        
        // ═══ 推送颜色事件 ═══
        notify_color_subscribers(batch);
        
        batch.clear();
    }
    
    LOG_INFO("Output worker thread stopped");
}
```

### 12.4 同 Fiber 去重

```cpp
void FiberMaintServiceImpl::deduplicate_batch(std::vector<ColorChangeRecord>& batch) {
    // 同一 fiber_id 在批次内多次变化，只保留最终状态
    // 例：GREEN→YELLOW→RED 合并为 GREEN→RED
    
    std::unordered_map<int32_t, size_t> first_occurrence;  // fiber_id → 首次出现位置
    std::vector<ColorChangeRecord> deduped;
    
    for (auto& record : batch) {
        auto it = first_occurrence.find(record.fiber_id);
        if (it == first_occurrence.end()) {
            first_occurrence[record.fiber_id] = deduped.size();
            deduped.push_back(record);
        } else {
            // 更新最终颜色，保留初始颜色
            deduped[it->second].new_color = record.new_color;
            deduped[it->second].timestamp_ms = record.timestamp_ms;
        }
    }
    
    // 移除 old_color == new_color 的无效记录
    deduped.erase(
        std::remove_if(deduped.begin(), deduped.end(),
            [](const ColorChangeRecord& r) { return r.old_color == r.new_color; }),
        deduped.end());
    
    batch = std::move(deduped);
}
```

```cpp
    // 网元内连纤连接：有源盘 ←→ 无源盘
    int32_t passive_board = 0;

    if (fiber_by_id_.at(intra_fiber.src_board_id).dst_board_type == BoardType::PASSIVE) {

        passive_port  = intra_fiber.src_port_id;
    } else {
        passive_board = intra_fiber.dst_board_id;
        passive_port  = intra_fiber.dst_port_id;

    auto inter_fiber_id = find_inter_ne_fiber_by_port(passive_board, 1);
    if (!inter_fiber_id) {
        return;  // Q21: Port-1 无网元间连纤，不影响颜色
```

## 14. 闪断抑制机制

### 14.1 两级防护

| 级别             | 位置                           | 机制                      | 作用                         |
| ---------------- | ------------------------------ | ------------------------- | ---------------------------- |
| **L1: 事件合并** | 入队侧（CoalescingEventQueue） | 同key覆盖，保留最新       | 减少无效事件数量（主要手段） |
| **L2: 输出抑制** | 输出侧（output_worker）        | 同fiber去重，保留最终状态 | 减少无效DB写入和推送         |

### 14.2 事件合并效果

```
闪断场景（1秒内同一告警翻转10次）：

  无合并：10次事件 → 10次颜色计算 → 可能10次DB写入
  有合并：10次事件 → 1次事件（最终状态）→ 1次颜色计算 → 0或1次DB写入

减少比例：90%
```

### 14.3 可选：消费侧 FlapDetector（第二阶段）

```cpp
// 仅在事件合并不足以应对极端场景时启用
class FlapDetector {
    struct FlapState {
        int64_t window_start_ms = 0;
        uint16_t flip_count = 0;
        bool suppressed = false;
        int64_t suppress_until_ms = 0;
    };
    
    std::unordered_map<AlarmCacheKey, FlapState, AlarmCacheKeyHash> states_;
    
    static constexpr uint16_t FLAP_THRESHOLD = 10;      // 1秒内翻转超过10次
    static constexpr int64_t  SUPPRESS_MS    = 2000;    // 抑制2秒
    
public:
    // 返回 true = 应抑制（不触发重算）
    bool should_suppress(const AlarmCacheKey& key, int64_t now_ms) {
        auto& state = states_[key];
        
        if (now_ms - state.window_start_ms > 1000) {
            state.window_start_ms = now_ms;
            state.flip_count = 0;
        }
        state.flip_count++;
        
        if (state.flip_count > FLAP_THRESHOLD && !state.suppressed) {
            state.suppressed = true;
            state.suppress_until_ms = now_ms + SUPPRESS_MS;
            LOG_WARN("Flap detected on port {}/{}, suppressing for 2s", 
                     key.board_id, key.port_id);
            return true;
        }
        
        if (state.suppressed) {
            if (now_ms >= state.suppress_until_ms) {
                state.suppressed = false;
                state.flip_count = 0;
                return false;  // 抑制解除，触发一次重算
            }
            return true;
        }
        
        return false;
    }
};
```

```cpp
void FiberMaintServiceImpl::alarm_stream_loop() {
    while (running_.load()) {
        LOG_INFO("Connecting to AlarmService stream...");
        
        auto stream = alarm_stub_->SubscribeAlarms(&context, request);
        if (!stream) {
            LOG_ERROR("Failed to create alarm stream");
            std::this_thread::sleep_for(std::chrono::seconds(5));
            continue;
        }
        
        AlarmEvent event;
        while (stream->Read(&event)) {
            event_queue_.push_alarm(event);
        }
        
        // Stream 断开
        LOG_WARN("Alarm stream disconnected, reconnecting in 5s...");
        std::this_thread::sleep_for(std::chrono::seconds(5));
        
        // 重连后全量刷新告警缓存
        reload_alarm_cache();
    }
}

void FiberMaintServiceImpl::fiber_stream_loop() {
    while (running_.load()) {
        LOG_INFO("Connecting to TopologyService stream...");
        
        auto stream = topo_stub_->SubscribeFiberEvents(&context, request);
        if (!stream) {
            LOG_ERROR("Failed to create fiber stream");
            std::this_thread::sleep_for(std::chrono::seconds(5));
            continue;
        }
        
        FiberEvent event;
        while (stream->Read(&event)) {
            event_queue_.push_fiber(event);
```

### 16.2 DB 写入失败处理

```cpp
void FiberMaintServiceImpl::batch_upsert_fiber_colors(
    const std::vector<ColorChangeRecord>& batch) 
{
    constexpr int MAX_RETRY = 3;
    
    for (int attempt = 1; attempt <= MAX_RETRY; ++attempt) {
        try {
            auto conn = db_pool_.acquire();
            conn->execute(build_upsert_sql(batch));
            return;  // 成功
        } catch (const DBException& e) {
            LOG_WARN("DB write failed (attempt {}/{}): {}", attempt, MAX_RETRY, e.what());
            if (attempt < MAX_RETRY) {
                std::this_thread::sleep_for(std::chrono::milliseconds(100 * attempt));
            }
        }
    }
    
    // 3次重试失败：记录到本地文件，待恢复后补写
    LOG_ERROR("DB write failed after {} retries, saving to local file", MAX_RETRY);
    save_to_local_wal(batch);  // Write-Ahead Log
}
```

```cpp
    fiber_stream_thread_ = std::thread(&FiberMaintServiceImpl::fiber_stream_loop, this);

    timer_thread_ = std::thread(&FiberMaintServiceImpl::timer_loop, this);
```

```cpp
void FiberMaintServiceImpl::shutdown() {
    LOG_INFO("Shutting down FiberMaintService...");
    
    // 1. 停止接收
    running_.store(false, std::memory_order_release);
    
    // 2. 等待 Stream 线程退出
    if (alarm_stream_thread_.joinable()) alarm_stream_thread_.join();
    if (fiber_stream_thread_.joinable()) fiber_stream_thread_.join();
    
    // 3. 等待事件处理线程消费完剩余事件
    if (event_process_thread_.joinable()) event_process_thread_.join();
    
    // 4. 等待输出线程刷完剩余变更
    if (output_thread_.joinable()) output_thread_.join();
    
    // 5. 停止定时任务
    if (timer_thread_.joinable()) timer_thread_.join();
    
    LOG_INFO("FiberMaintService shutdown complete");
}
```

```yaml
    suppress_ms: 2000             # 抑制时长
    
  # 定时任务
  timer:
    trend_interval_sec: 300       # 趋势采集间隔
    cleanup_changes_days: 30      # 变更记录保留天数
    cleanup_trend_days: 7         # 趋势数据保留天数
    
  # 重连
  reconnect:
    alarm_stream_interval_sec: 5  # 告警流重连间隔
    fiber_stream_interval_sec: 5  # 拓扑流重连间隔
```

### 20.3 关键设计决策记录

| 决策          | 选项                    | 选择               | 理由                   |
| ------------- | ----------------------- | ------------------ | ---------------------- |
| 事件消费模型  | 多线程+锁 / 单线程串行  | **单线程串行**     | 消除所有竞态，性能够用 |
| 告警缓存模型  | 计数器 / 存在性         | **存在性**         | 对齐 R-26/R-27         |
| 依赖索引 Key  | 含 alarm_level / 不含   | **不含**           | 任何级别变化都需重算   |
| FIBER_CREATED | RPC获取 / 事件携带      | **事件携带**       | 消除阻塞，事件自包含   |
| 闪断处理      | 消费侧抑制 / 入队侧合并 | **入队侧合并为主** | 更简单，效果更好       |
| 场景扩展      | 修改核心函数 / 策略模式 | **策略模式**       | 开闭原则               |
| 依赖构建      | 硬编码 / 策略自声明     | **策略自声明**     | 零硬编码，通用化       |
| DB 写入       | 同步 / 异步批量         | **异步批量**       | 不阻塞计算             |
| 队列满时      | 丢弃 / 阻塞             | **阻塞（背压）**   | NF-17 不可丢弃         |
