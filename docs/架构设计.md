## 1. 概述

### 1.1 文档目的

本文档描述光纤维护服务系统的技术架构设计，包括系统分层、服务拆分、通信机制、缓存设计、事件驱动架构、数据库设计及关键流程设计。

### 1.2 技术栈

| 模块             | 技术选型                            |
| ---------------- | ----------------------------------- |
| 后端语言         | C++17                               |
| RPC 框架         | gRPC + Protocol Buffers 3           |
| API Gateway      | 独立进程（C++ 自研 / Envoy）        |
| 前端协议         | REST (JSON) + WebSocket             |
| 数据库           | MySQL 8.0 (InnoDB, utf8mb4)，5 实例 |
| 事件推送（内部） | gRPC Server-Side Streaming          |
| 事件推送（外部） | WebSocket / SSE                     |
| 异步任务         | Pull Call 模式                      |
| 数据分区         | MySQL RANGE 分区（按月）            |

## 3. 事件驱动架构

### 3.1 事件订阅矩阵

| 事件源          | 事件                  | 消费方            | 用途                                      |
| --------------- | --------------------- | ----------------- | ----------------------------------------- |
| BoardService    | BOARD_CREATED/DELETED | TopologyService   | 维护端口缓存                              |
| BoardService    | BOARD_DELETED         | FiberMaintService | 删除有源盘触发关联连纤颜色重算            |
| TopologyService | FIBER_CREATED/DELETED | FiberMaintService | 更新连纤缓存+颜色重算                     |
| AlarmService    | ALARM_RAISED/CLEARED  | FiberMaintService | 更新告警缓存+颜色重算                     |
| FiberMaintService | FIBER_COLOR_CHANGED | API Gateway       | 连纤颜色变化实时推送（WebSocket）         |

### 3.2 订阅关系图

```
BoardService ──BoardEvent──→ TopologyService
BoardService ──BoardEvent──→ FiberMaintService（仅BOARD_DELETED触发颜色重算）
TopologyService ──FiberEvent──→ FiberMaintService
AlarmService ──AlarmEvent──→ FiberMaintService
FiberMaintService ──FiberColorEvent──→ API Gateway（gRPC Stream）
```

### 3.3 事件传递链路

```
[单盘变更] BoardService → BoardEvent → TopologyService + FiberMaintService
[连纤变更] TopologyService → FiberEvent → FiberMaintService
[告警变更] AlarmService → AlarmEvent → FiberMaintService
[颜色变更] FiberMaintService → FiberColorEvent → API Gateway → WebSocket → 前端
```

## 4. FiberMaintService 缓存设计

### 4.1 连纤缓存（方案C）

#### 设计目的

解决 FIBER_DELETED 事件仅携带 fiber_id、DB 已删除无法回查的问题。

#### 数据结构

```cpp
struct FiberCacheEntry {
    int32_t fiber_id;
    int32_t src_board_id;  int8_t src_port_id;  int32_t src_ne_id;
    int32_t dst_board_id;  int8_t dst_port_id;  int32_t dst_ne_id;
    bool    is_inter_ne;
};

std::unordered_map<int32_t, FiberCacheEntry> fiber_by_id_;
std::unordered_multimap<std::pair<int32_t,int8_t>, int32_t> fiber_by_port_;  // 双向索引
```

#### 维护时机

| 时机          | 操作                                  |
| ------------- | ------------------------------------- |
| 服务启动      | BatchGetFibers 全量加载               |
| FIBER_CREATED | GetFiber → INSERT 缓存                |
| FIBER_DELETED | 从缓存读取（DB已删）→ 处理 → 删除缓存 |
| 断线重连      | 全量刷新                              |

### 4.2 告警缓存

#### 设计原则

| 原则           | 说明                                                         |
| -------------- | ------------------------------------------------------------ |
| 唯一性         | 同一端口(board_id+port_id)同一告警类型(alarm_level)只存一条  |
| 存在即激活     | 缓存中存在记录 → 该端口有该级别告警                          |
| 不存在即无告警 | 缓存中无记录 → 该端口无该级别告警                            |
| 与DB对齐       | 与 current_alarms PK(board_id, port_id, alarm_level) 一一对应 |

#### 数据结构

```cpp
struct AlarmCacheKey {
    int32_t board_id;
    int8_t  port_id;
    int8_t  alarm_level;   // 1=CRITICAL, 2=MINOR
    bool operator==(const AlarmCacheKey& o) const;
};

struct AlarmCacheValue {
    Timestamp raised_at;
};

std::unordered_map<AlarmCacheKey, AlarmCacheValue, AlarmCacheKeyHash> alarm_cache_;
```

#### 缓存操作

| 操作     | 触发          | 行为                                  |
| -------- | ------------- | ------------------------------------- |
| INSERT   | ALARM_RAISED  | `alarm_cache_[{b,p,l}] = {raised_at}` |
| DELETE   | ALARM_CLEARED | `alarm_cache_.erase({b,p,l})`         |
| 全量加载 | 启动/断线重连 | Pull Call → clear → 逐条写入          |
| EXISTS   | 颜色计算      | `alarm_cache_.count({b,p,l}) > 0`     |

#### 查询接口

```cpp
bool has_alarm(int32_t board_id, int8_t port_id, int8_t alarm_level);

struct PortAlarmSummary { bool has_critical; bool has_minor; };
PortAlarmSummary get_port_alarm_summary(int32_t board_id, int8_t port_id);
```

### 4.3 颜色缓存

#### 设计目的

为查询接口提供高性能的颜色数据访问，避免每次查询都访问数据库，提升响应速度。

#### 数据结构

```cpp
struct FiberColorCacheEntry {
    int8_t color;          // 1=GREEN, 2=RED, 3=YELLOW
    int32_t scene_type;    // 场景类型：1=直连有源盘, 2=经无源盘
    int32_t scenario_case; // 场景细分：0=无, A/B/C
};

std::unordered_map<int32_t, FiberColorCacheEntry> color_by_fiber_;
```

#### 缓存操作

| 操作     | 触发                | 行为                                                                 |
| -------- | ------------------- | -------------------------------------------------------------------- |
| INSERT/UPDATE | 颜色重算完成       | 更新 `color_by_fiber_[fiber_id]`，同步更新数据库                      |
| DELETE   | 连纤删除/单盘删除   | 从缓存中删除对应条目                                                  |
| 全量加载 | 服务启动           | 从数据库 `fiber_colors` 表全量加载                                    |
| READ     | 查询接口调用       | 直接从缓存读取，无需访问数据库                                        |

#### 缓存一致性

| 操作       | 缓存更新          | 数据库更新        | 事件推送          |
| ---------- | ----------------- | ----------------- | ----------------- |
| 颜色重算   | 同步更新缓存      | 同步写入数据库    | 推送 FiberColorEvent |
| 连纤删除   | 同步删除缓存      | 同步删除数据库    | 无需推送          |
| 单盘删除   | 同步删除关联缓存  | 无需操作          | 无需推送          |

#### 查询接口优化

| 接口 | 优化前 | 优化后 |
| ---- | ------ | ------ |
| GetColoredFibers | 查询数据库 fiber_colors | 读取 color_by_fiber_ 缓存 |
| GetAllColoredFibers | 查询数据库 fiber_colors | 读取 color_by_fiber_ 缓存 |
| GetFiberStatsRealtime | 查询数据库聚合统计 | 遍历 color_by_fiber_ 统计 |

## 5. 颜色重算机制设计

### 5.1 总体流程

颜色重算分为**告警消息触发**和**连纤消息触发**两大类，均通过本地缓存完成判定，不实时调用外部 RPC。

### 5.2 告警消息触发

```
AlarmEvent → 更新 alarm_cache_ → 两跳寻路 → 判断宿端/源端 → 判定场景
→ 从 alarm_cache_ 读取告警 → 计算颜色 → 比较更新
```

#### 两跳寻路

| 第一跳结果                        | 处理                     |
| --------------------------------- | ------------------------ |
| 网元间连纤，本端口是 dst          | 场景1，单跳完成          |
| 网元间连纤，本端口是 src          | 源端，跳过               |
| 网元内连纤，对端是无源盘 Port-2/3 | 第二跳→Port-1→网元间连纤 |
| 网元内连纤，对端是有源盘          | 跳过                     |
| 无关联连纤                        | 跳过                     |

### 5.3 连纤消息触发

```
FiberEvent → 更新 fiber 缓存 → 判断连纤类型
├─ 网元间: 创建→初始化颜色 / 删除→移除
└─ 网元内: 场景变更 → 查Port-1关联网元间连纤 → 从 alarm_cache_ 读取 → 重算
```

#### 场景变更矩阵

| 操作                | 影响端口          | 场景变更 | 颜色影响     |
| ------------------- | ----------------- | -------- | ------------ |
| 创建网元内(↔Port-2) | Port-2: 空闲→占用 | C→A/B    | 可能绿→红/黄 |
| 删除网元内(↔Port-2) | Port-2: 占用→空闲 | A/B→C    | 强制绿       |
| 创建网元内(↔Port-3) | Port-3: 空闲→占用 | B→A      | 逻辑变更     |
| 删除网元内(↔Port-3) | Port-3: 占用→空闲 | A→B      | 逻辑变更     |
| 创建网元间          | 新连纤            | 新增     | 初始化       |
| 删除网元间          | 被删连纤          | 移除     | 移除         |

### 5.4 单盘删除触发

```
BoardEvent(BOARD_DELETED) → 两跳寻路找关联网元间连纤 → 触发颜色重算
→ 更新 color_by_fiber_ 缓存 → 删除数据库记录 → 删除颜色缓存条目
```

#### 触发场景

| 单盘类型 | 删除后影响 | 处理方式 |
| -------- | ---------- | -------- |
| 有源盘（场景1宿端） | 关联网元间连纤颜色变为GREEN | 触发颜色重算 |
| 有源盘（场景2同层次） | 场景A/B→C，颜色可能变化 | 触发颜色重算 |
| 无源盘 | 关联网元间连纤场景变更 | 触发颜色重算 |

### 5.5 颜色变化事件推送

当连纤颜色发生变化时，FiberMaintService 主动推送 FiberColorEvent 给所有订阅者（API Gateway）。

#### 推送时机

| 时机 | 推送条件 |
| ---- | -------- |
| 颜色重算完成 | `old_color != new_color` |
| 连纤创建（非绿色） | 初始颜色为RED/YELLOW |

#### FiberColorEvent 结构

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| fiber_id | int32 | 连纤ID |
| fiber | FiberInfo | 连纤详细信息 |
| old_color | FiberColor | 变化前颜色 |
| new_color | FiberColor | 变化后颜色 |
| scene_type | int32 | 场景类型 |
| scenario_case | int32 | 场景细分 |
| timestamp | string | 时间戳 |

### 5.5 并发控制（待进一步设计）

| 读写锁   | alarm_cache_ / fiber_colors 加锁   |

## 6. 断线重连与增量补偿

### 6.1 内部 Stream 断线

| 订阅方            | 订阅源          | 重连策略         | 补偿                                     |
| ----------------- | --------------- | ---------------- | ---------------------------------------- |
| FiberMaintService | AlarmService    | 指数退避(1s→60s) | Pull Call → 重建 alarm_cache_ → 全量重算 |

| 步骤 | 说明                               |
| ---- | ---------------------------------- |
| 1    | 心跳超时检测（30s）                |
| 2    | 指数退避重连（1s→60s）             |
| 3    | 重连后全量拉取（有颜色连纤、统计） |
| 4    | 重新 subscribe                     |

## 7. 关键流程设计

### 7.1 单盘删除级联流程

```
BoardService.DeleteBoard(board_id=5)
  ├─ TopologyService.GetBoardFibers(5) → [F001, F002]
  ├─ TopologyService.DeleteFiber(F001) → FiberEvent → FiberMaintService
  ├─ TopologyService.DeleteFiber(F002) → FiberEvent → FiberMaintService
  ├─ DELETE FROM boards WHERE board_id=5
  └─ (最后) BoardEvent → TopologyService
```

### 7.2 FiberMaintService 启动流程

```
启动
  → Pull Call → 全量当前告警 → 构建 alarm_cache_
  → BatchGetFibers → 全量连纤 → 构建 fiber_by_id_ / fiber_by_port_
  → 逐条网元间连纤计算颜色（读 alarm_cache_）→ 写 fiber_colors
  → 订阅 AlarmEvents + FiberEvents
  → 启动 5min 定时任务
  → 就绪
```

### 7.3 性能归档流程

```
[每 15min]
  → SELECT * FROM current_performance
  → INSERT INTO history_performance
  → DELETE FROM current_performance（清空）
```

### 8.2 核心 DDL

#### boards

```sql
CREATE TABLE boards (
    board_id       INT            NOT NULL,
    board_type     TINYINT        NOT NULL,
    ne_id          INT            NOT NULL,
    port_id        TINYINT        NOT NULL,
```


#### current_performance / history_performance

```sql
CREATE TABLE current_performance (

CREATE TABLE history_performance (
    board_id       INT            NOT NULL,
    port_id        TINYINT        NOT NULL,
    recorded_at    TIMESTAMP      NOT NULL,
    oop_value      DECIMAL(10,4)  NULL,
    iop_value      DECIMAL(10,4)  NULL,
    PRIMARY KEY (board_id, port_id, recorded_at),
    INDEX idx_board_time (board_id, recorded_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4
  PARTITION BY RANGE (YEAR(recorded_at) * 100 + MONTH(recorded_at)) (
    PARTITION p202607 VALUES LESS THAN (202608),
    PARTITION p202608 VALUES LESS THAN (202609),
    PARTITION p202609 VALUES LESS THAN (202610),
    PARTITION p_future VALUES LESS THAN MAXVALUE
  );
```

```sql
    fiber_id       INT            NOT NULL,

    updated_at     TIMESTAMP      DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (fiber_id),
    INDEX idx_color (color)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```
