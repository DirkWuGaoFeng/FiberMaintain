## 发现并修复的问题

| 编号 | 严重程度 | 描述 | 修复方案 |
|------|----------|------|----------|
| BUG-1 | **Critical** | `sse.ts` 的 `parseSSEStream` 使用 `\n\n` 分割 SSE 事件块，但 `sse_starlette` 实际发送 `\r\n\r\n`（CRLF），导致所有事件留在 buffer 中从未被解析 | 改用正则 `/\r?\n\r?\n/` 分割事件块，`/\r?\n/` 分割行 |
| BUG-2 | **High** | `chat.ts` 中 `assistantMsg` 为普通对象，SSE handlers 闭包修改 `assistantMsg.content` 绕过 Vue reactive proxy，`MessageBubble.vue` 的 `renderedContent` computed 缓存空值不重新计算 | 使用 `reactive()` 包装 `assistantMsg` |

## 已知限制

1. **C++ 后端数据缺失**: `fiber_maint_service` 启动时无法从 `topology_service` 同步光纤缓存（gRPC 连接失败），导致所有光纤查询返回 "Not found" → Agent 降级为错误提示
2. **Ollama 未启动**: 非规则命中的查询（如 "今天天气"）无法走 LLM 路径
3. **pytest-asyncio fixture 问题**: `tests/integration/test_server_api.py` 存在预置 fixture 解析问题（非本次引入）

## 结论

前端界面显示问题已完全修复。根因是 **SSE 事件分隔符不兼容**（`\r\n\r\n` vs `\n\n`）和 **Vue 响应式缺陷**（普通对象绕过 proxy）。修复后，所有工作流场景的前端显示均正常工作，SSE 事件正确解析并渲染到 UI。
