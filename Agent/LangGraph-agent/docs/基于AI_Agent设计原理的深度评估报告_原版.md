## 一、评估体系分析（tests/eval）

### 1.1 评估体系已实现的功能

本系统已实现一套**分层评估体系**，包含 7 个文件，对标书中第六章（Agent 的评估）的多个核心概念：

| 文件 | 功能 | 对标书中概念 |
|------|------|-------------|
| `runner.py` | 规则层快速评估（零 LLM，日常门禁） | 评估环境、自动化评估 |
| `e2e_runner.py` | 端到端评估（真实图执行） | 端到端回归、状态验证 |
| `checks.py` | 8 类确定性检查器 | 确定性检查先行、失败归因 |
| `rubric_judge.py` | LLM-as-a-Judge 四维评判 | LLM-as-a-Judge、Rubric 评判 |
| `failure_diagnosis.py` | 错误归因聚合 + Pass@k + McNemar 显著性 | 失败归因、统计显著性 |
| `qa_dataset.json` | 50 条 QA 标注集（含 v8 映射） | 评估数据集设计 |
| `e2e_dataset.json` | 30 条端到端测试用例 | 评估环境 + 数据集 |

## 二、系统架构总览

| 维度 | 实现 |
|------|------|
| **版本** | v7.1-Final（18节点）+ v8 实验架构（三层） |
| **编排框架** | LangGraph StateGraph |
| **节点数** | 18（v7.1）/ 5（v8） |
| **LLM 梯度** | 三层：14b（分析/报告）→ 7b（叙述/知识）→ 3b（紧急兜底） |
| **工具数** | 23+ REST API 工具 |
| **Skills** | 16 个 YAML Skill 定义 |
| **评估用例** | 50 条 QA + 30 条 E2E |
| **后端** | C++ 光纤维护服务（WSL） |
| **前端** | Vue 3 + TypeScript |

### 核心架构图

```
用户输入
  ↓
input_guard（注入检测 + 上下文压缩）
  ↓
rule_engine（27+ 条正则规则，零 LLM，< 10ms）
  ↓
┌─── fast_path ──→ fast_path_executor ──→ result_aggregator → END
│
├─── rule_hit_complex ──→ param_gate → intent_router → ...
│
└─── rule_miss ──→ intent_classifier（14b LLM）→ param_gate → intent_router
                                                              ↓
                                               ┌── data_collector（ReAct Agent）
                                               ├── batch_dispatcher
                                               ├── knowledge_qa（RAG）
                                               └── chitchat → result_aggregator → END
                                                        ↓
                                               rule_judgment（程序化阈值，零 LLM）
                                                        ↓
                                               analysis_expert（14b LLM）
                                                  ↓           ↓
                                          need_more_data    direct_narrate / generate_report
                                          (ReAct loop)         ↓
                                                        narrator（7b LLM）
                                                              ↓
                                                   narrator_validator（零 LLM，数字校验）
                                                      ↓              ↓
                                                    pass          fail → template_fallback
                                                      ↓              ↓
                                               result_aggregator → END
```

| **业务规则细化** | ✅ Skill YAML 中 judgment 条件精确到阈值级别；thresholds.yaml 唯一权威源 | ⭐⭐⭐⭐⭐ |

| **上下文压缩** | ✅ `ContextCompressor`：LLM摘要+确定性实体提取，替代滑动窗口 | ⭐⭐⭐⭐⭐ |
| **提示注入防御** | ✅ 双层检测：强规则（拦截）+ 弱规则（标记疑似留痕） | ⭐⭐⭐⭐⭐ |
| **指令与数据分离** | ✅ analysis_expert 的 user.md + external.md 分离可信/低信任内容 | ⭐⭐⭐⭐⭐ |

**特别亮点：**

1. **状态栏实现完美对标书中原则**：
   - 纯代码维护（零LLM）→ 书中"用代码维护，不用LLM维护"
   - 注入到 user 消息末尾 → 书中"动态信息追加末尾"
   - 包含预算/失败/停滞风险 → 书中"把隐式状态显式化"
   - 模型无条件信任 → 书中"状态栏内容只来自事实"

2. **指令与数据分离架构**：
   - `system.md`：完全静态角色定义（KV Cache 前缀稳定）
   - `user.md`：系统可信数据（rule_judgment、data_summary、status_bar）
   - `external.md`：外部低信任内容（经验/RAG/对话摘要），带 `<external_content trust="low">` 标记

3. **上下文压缩三级降级**：
   - LLM 摘要压缩（首选）→ 简单预览 fallback → 滑动窗口兜底

### 📗 第3章：用户记忆和知识库 — ⭐⭐⭐⭐ 良好

| 书中原则 | 本系统实现 | 评分 |
|----------|-----------|------|
| **用户记忆层次** | ✅ UserMemory（偏好注入）+ ExperienceStore（故障经验）+ MemoryRetriever（语义检索） | ⭐⭐⭐⭐ |
| **记忆格式** | ✅ SQLite WAL 模式 + JSON 偏好 + 经验条目（带版本控制） | ⭐⭐⭐⭐ |
| **RAG 混合检索** | ✅ ChromaDB 向量(0.6) + BM25 关键词(0.4) + 查询改写 | ⭐⭐⭐⭐⭐ |
| **知识更新机制** | ✅ Consolidator 离线整合（合并/过期/淘汰），质量门禁 | ⭐⭐⭐⭐⭐ |
| **经验质量门禁** | ✅ `_passes_quality_veto()` 检查数字能否溯源到证据 | ⭐⭐⭐⭐⭐ |
| **智能体化 RAG** | ⚠️ 部分实现：query_rewriter 改写查询，但无多轮迭代检索 | ⭐⭐⭐ |
| **双层记忆架构** | ✅ UserMemory 偏好（常驻）+ RAG 按需检索 | ⭐⭐⭐⭐ |

**亮点：**
- **ExperienceStore 质量门禁**：写入前检查结论中数字能否溯源到证据，防止幻觉经验污染
- **Consolidator 离线整合**：周期性合并相似经验（Bigram Jaccard 相似度 0.45）、淘汰过期条目（180天）、超量淘汰（每 fiber 最多 20 条）
- **MemoryRetriever 三级检索**：精确匹配 → 模糊匹配（跨 fiber）→ 语义检索（embedding 余弦相似度 0.7）

**改进空间：**
- 缺少上下文感知检索（Contextual Retrieval）：在分块前用 LLM 生成前缀摘要
- RAG 检索后未实现 Cross-Encoder 重排序

| **沙盒隔离** | ✅ _http_client 统一调用后端，三态熔断器+背压控制+指数退避重试 | ⭐⭐⭐⭐⭐ |
| **幂等性** | ✅ batch_dispatcher 的 idempotency_key | ⭐⭐⭐⭐ |
| **事件驱动异步架构** | ✅ events/listener.py + router.py（WebSocket 推送） | ⭐⭐⭐⭐ |

| **人在回路（HITL）** | ✅ confirmation_gate 令牌机制（TTL 10分钟，MAX_PENDING 50） | ⭐⭐⭐⭐⭐ |

**亮点：**
- **HTTP 客户端弹性工程**：三态熔断器（CLOSED→OPEN→HALF_OPEN）+ 背压控制器（20条滑动窗口，错误率>10%时线性增加延迟）+ 指数退避重试（最多3次）
- **ToolReviewer 三级决策**：allow/block/review，非高风险工具仅做参数类型抽查，高风险工具完整复核
- **confirmation_gate**：令牌机制替代同步等待，不阻塞 Agent 主循环；TTL + MAX_PENDING 双重保护
