# 组件砍除辩护话术与深研计划

> 日期：2026-08-06 | 用途：面试防御素材（并入《面试准备与项目复盘》Agent 章节）+ 技术补课路线
> 前置阅读：`docs/plans/2026-08-06-improvement-checklist-v2.md`（实施清单）

---

## 1. 辩护总纲：一句话哲学

> **"这个系统的设计哲学是'规则优先、LLM 兜底'——能用确定性逻辑解决的绝不用 LLM，能用自研基础设施解决的绝不引第三方框架。砍掉的每一个组件都服务于'开放性/生态/多用户'场景，而这是一个内网单团队的封闭运维系统。"**

任何"为什么不用 X"的问题，回答骨架固定为三问：

1. **X 解决什么问题**（证明你懂它）
2. **我的场景为什么没有这个问题**（证明砍除是理性决策而非不知道有它）
3. **我有什么补偿机制 / 什么信号会触发引入**（证明这是延迟决策而非永久无知）

## 2. 逐项辩护话术

### 2.1 MCP（说服力：强）

**它解决什么**：跨厂商/跨 Agent 的工具与上下文接入标准化，本质是"AI 的 USB 协议"——resource/tool/prompt 三原语 + stdio/HTTP 传输层。

**为什么砍**：协议价值 = 生态规模。我的系统是封闭系统，16 个工具全部指向自研 C++ 后端 API Gateway，MCP 零消费者；引入它只有协议开销没有收益。我用 Skill YAML 实现了自己的工具注册层（声明式 trigger/routing/judgment + 热加载），解决的是同一个问题在单系统内的形态。

**触发引入的信号**：当工具需要被第二个 Agent（如 deer-flow-agent）复用时。

### 2.2 Reranker（说服力：强）

**它解决什么**：混合检索召回的 top-K 里仍有噪声文档，reranker 用 cross-encoder 对 query-doc 对精排。

**为什么砍**：可量化——知识库只有 15 篇文档。Reranker 的收益在千级语料上才显现，这个规模下 ChromaDB 向量(0.6) + BM25(0.4) + query rewrite 已经足够。

**触发引入的信号**：文档数 > 100，或评估集显示知识问答召回命中率下降。

### 2.3 多 Agent Supervisor（说服力：强）

**它解决什么**：异构专业角色协作（如研究员+编码者+评审员），通过任务委派和消息传递完成单 Agent 能力边界外的复杂任务。

**为什么砍**：渐进复杂度原则——单 Agent + 工具调用能覆盖 80% 场景，我的 18 节点图已通过子图（data_collector/knowledge_assistant）实现了职责分离。同时我保留了 v8 三层架构实验（lead_router → orchestrator），证明这是"能做但选择不做"。

**追问应对**："那你怎么看待多 Agent？" → 讲 v8 设计：LeadRouter 产出 ExecutionPlan、Orchestrator 调度子任务，以及为什么它还在实验阶段（评估集对比还没跑出结论）。

### 2.4 Mem0（说服力：中强，需能讲原理）

**它解决什么**：通用 Agent 长期记忆管道——extraction（从对话抽取事实）→ consolidation（去重/冲突消解/更新）→ retrieval（语义召回注入上下文）。

**为什么砍**：我的记忆需求是单一实体类型（光纤维度的故障经验），不是开放域用户画像。在已有 SQLite 记忆基础设施上加一张经验表即可，引 Mem0 是重复造轮子 + 新增依赖。

**追问应对**：必须能讲 Mem0 三阶段管道的原理（见第 3 节学习计划 B）。

### 2.5 LangFuse 推迟（说服力：中）

**为什么推迟**：自研 RequestTracer（全链路 Span）+ 前端 Monitor（概览卡片/Token 图表/Trace 瀑布图）已覆盖可观测性需求。

**追问应对**："为什么造轮子不用现成的？" → 领域指标问题：规则命中率、降级等级、处理路径分布这些领域维度，LangFuse 的通用 Trace/Span schema 表达不了，硬塞反而丢失语义。

### 2.6 HITL（最弱项，需主动防御）

**事实**：`pull_call_create`/`pull_call_cancel` 是真实写操作，"系统只读所以不需要 HITL"不成立。

**辩护（写操作风险分级理论）**：

> "不是所有写操作都需要人工审批，关键看**可撤销性**和**影响半径**。pull-call 是发起测试请求——可轮询、可取消、不改配置不删数据，影响半径是单个光纤的一次测试。这类低风险写操作我用 参数门禁（Pydantic 强校验）+ 审计日志（audit.jsonl）+ 输入防护 三重补偿。真正的 HITL 应该留给高风险写操作——配置变更、批量操作。"

**加分动作**：改进清单 P1-B 落地后（pull_call_create 前置确认卡片），话术升级为"我按风险分级实现了轻量 HITL"，从解释缺失变成展示设计。

### 2.7 PII 输入侧（已知漏洞，诚实承认）

输出方向有过滤器（IP/端口/堆栈脱敏），但输入方向用户粘贴的敏感内容会直接进 LLM。内网场景风险有限，被问到就承认是已知 TODO + 说出方案（发送前检测/脱敏）。诚实 > 硬辩。

## 3. 组件原理深研计划

**策略**：深度优先（手写 mini 实现）+ 实验驱动（利用已有标注集），原理级广度兜底。
**核心原则**：把研究绑定到即将实施的 P0/P1 工作上，边做边学，零额外时间成本。

### A. Checkpointer 与状态持久化（绑定 P0-B，最高优先级）

| 项 | 内容 |
|---|---|
| 研究问题 | LangGraph 状态机如何在任意节点中断/恢复？checkpoint 的数据结构是什么（channel values / versions / pending writes）？SqliteSaver 的表结构？ |
| 方法 | 实施 SqliteSaver 时直接读 `langgraph-checkpoint-sqlite` 源码；完成后打开 checkpoints.db 用 SQLite 工具看真实表结构 |
| 产出 | 面试话术："我能讲清 checkpoint 如何记录每个 superstep 后的通道状态，以及 thread_id/checkpoint_id 的寻址方式" |

### B. 记忆系统（绑定 P1-A）

| 项 | 内容 |
|---|---|
| 研究问题 | Mem0 的 extraction/consolidation/retrieval 管道 vs 我的确定性写入方案，各自的取舍？ |
| 方法 | 读 Mem0 开源实现的核心管道（约 1 天）；实施经验记忆时对比自己的设计写一段取舍分析 |
| 产出 | 面试话术："我知道通用记忆管道怎么做，但我的场景选择了确定性触发——这是领域驱动的简化，不是不懂" |

### D. MCP 协议（砍掉但必须能讲，约半天）

| 项 | 内容 |
|---|---|
| 研究问题 | resource/tool/prompt 三原语的语义区别？stdio vs Streamable HTTP 传输的适用场景？能力协商（capability negotiation）流程？ |
| 方法 | 只读官方 spec + 一个官方 SDK 的 server 示例，不实施 |
| 产出 | 面试话术支撑 2.1 的辩护："我砍掉 MCP 不是因为不知道它，而是因为协议价值取决于生态规模" |

### C. RAG 实验驱动（可选，排后）

标注集（P0-C）建好后，可做对照实验：有/无 query rewrite 的知识问答命中率差异、向量/BM25 权重 0.6/0.4 vs 0.5/0.5。基础设施全部现成（RequestTracer 记录检索过程）。优先级低于 A/B/D，因为 RAG 当前不是瓶颈。

### 广度兜底清单（原理级即可，每个 30 分钟）

- ReAct 循环与 Plan-and-Execute 的区别及适用场景
- Reflexion / Self-Refine 模式（我的 report_evaluator 反思循环就是其变体——这是加分话术）
- Structured Output 的实现原理（function calling vs JSON mode vs constrained decoding）
- 向量检索 vs BM25 vs 混合检索的互补性原理

## 4. 面试问答预演（高频追问）

| 追问 | 应答要点 |
|---|---|
| "为什么不直接上 Dify/Coze？" | 低代码平台满足通用场景，但我的领域判定（颜色策略/阈值引擎）必须规则可控可审计，平台的黑盒编排不满足运维合规要求 |
| "你的 Agent 和直接写 if-else 有什么区别？" | 规则引擎处理确定性部分（快路径零 LLM），LLM 只处理规则覆盖不了的长尾（意图分类/分析/表达）——成本、延迟、可审计性三者兼得，用数据说话：规则命中率指标在 Monitor 页面可查 |
| "18 个节点会不会太重？" | 每个节点单一职责 + 条件路由，复杂度是业务固有的（输入防护→规则→意图→参数→采集→判定→分析→表达→校验）；且 v8 实验正在验证 3 节点极简形态的可行性 |
| "LLM 幻觉怎么防？" | 四道防线：rule_judgment 程序化判定（零 LLM 出数）、number_validator 数值校验、narrator_validator 表达校验、template_fallback 兜底 |
