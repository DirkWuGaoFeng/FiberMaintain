## 1. 日常运维操作

### 1.1 服务启停

```bash
# 全栈启动
docker compose up -d

# 全栈停止
docker compose down

# 全栈停止并清除数据卷（⚠️ 危险：删除所有持久化数据）
docker compose down -v

# 重启单个服务
docker compose restart deerflow
docker compose restart fiber-backend
docker compose restart ollama
docker compose restart frontend

# 查看服务状态
docker compose ps

# 查看资源占用
docker stats --no-stream
```

### 1.2 配置变更

```bash
# 1. 修改配置
vim config.yaml

# 2. 重建并重启（配置挂载为 volume，仅需重启）
docker compose restart deerflow

# 3. 验证配置生效
curl http://localhost:8000/api/v1/status | python -m json.tool
```

**热更新项（无需重启）**：

- 插件文件（`plugins/` 目录，5s 自动扫描）
- 知识库文档（通过管理界面上传/审核/入库）

**需重启项**：

- `config.yaml` 中的 LLM 地址、后端地址、端口
- `docker-compose.yaml` 中的资源限制、端口映射
- 环境变量变更

### 1.3 健康检查

```bash
# Agent 健康检查
curl -s http://localhost:8000/api/v1/health | python -m json.tool

# 后端健康检查
curl -s http://localhost:8080/health

# Ollama 健康检查
curl -s http://localhost:11434/api/tags

# ChromaDB 健康检查
curl -s http://localhost:8100/api/v1/heartbeat

# 一键全检脚本
bash scripts/health_check.sh
```

**`scripts/health_check.sh`**：

```bash
#!/bin/bash
# 全栈健康检查脚本
set -e

RED='\033[0;31m'
GREEN='\033[0;32m'
NC='\033[0m'

check() {
    local name=$1 url=$2
    if curl -sf --max-time 5 "$url" > /dev/null 2>&1; then
        echo -e "  ${GREEN}✅${NC} $name"
    else
        echo -e "  ${RED}❌${NC} $name"
    fi
}

echo "═══════════════════════════════════════"
echo " 光纤维护系统 健康检查 $(date '+%Y-%m-%d %H:%M:%S')"
echo "═══════════════════════════════════════"
check "Agent API       :8000"  "http://localhost:8000/api/v1/health"
check "Fiber Backend   :8080"  "http://localhost:8080/health"
check "Fiber WS        :8081"  "http://localhost:8081/health"
check "Frontend        :5173"  "http://localhost:5173/"
check "Ollama          :11434" "http://localhost:11434/api/tags"
check "ChromaDB        :8100"  "http://localhost:8100/api/v1/heartbeat"
check "Prometheus      :9090"  "http://localhost:9090/-/healthy"
check "Grafana         :3001"  "http://localhost:3001/api/health"
echo "═══════════════════════════════════════"
```

## 2. 日志管理

### 2.1 日志位置

| 服务           | 容器内路径                           | 宿主机挂载              | 说明                           |
| -------------- | ------------------------------------ | ----------------------- | ------------------------------ |
| Agent 应用日志 | `/var/log/fiber-agent/app.log`     | `agent_logs` volume   | 主日志                         |
| Agent MCP 审计 | `/var/log/fiber-agent/mcp.jsonl`   | `agent_logs` volume   | 后端调用审计                   |
| Agent 工具审计 | `/var/log/fiber-agent/audit.jsonl` | `agent_logs` volume   | 工具调用全链路                 |
| 后端日志       | `/var/log/fiber-backend/`          | `backend_logs` volume | C++ 服务日志                   |
| Ollama         | Docker stdout                        | —                      | `docker compose logs ollama` |
| 前端 Nginx     | `/var/log/nginx/`                  | 容器内                  | 访问日志                       |

### 2.2 日志查看

```bash
# 实时跟踪 Agent 日志
docker compose logs -f --tail=100 deerflow

# 查看最近 1 小时日志
docker compose logs --since=1h deerflow

# 查看 MCP 审计日志（JSONL 格式）
docker compose exec deerflow tail -50 /var/log/fiber-agent/mcp.jsonl | python -m json.tool

# 查看工具调用审计
docker compose exec deerflow tail -50 /var/log/fiber-agent/audit.jsonl

# 按 trace_id 追踪全链路
docker compose exec deerflow grep "abc123def456" /var/log/fiber-agent/mcp.jsonl
docker compose exec deerflow grep "abc123def456" /var/log/fiber-agent/audit.jsonl

# 后端日志
docker compose logs -f --tail=200 fiber-backend
```

### 2.3 日志轮转

```bash
# 创建 logrotate 配置
cat > /etc/logrotate.d/fiber-agent << 'EOF'
/var/lib/docker/volumes/fiber-maintenance-agent_agent_logs/_data/*.log {
    daily
    rotate 30
    compress
    delaycompress
    missingok
    notifempty
    copytruncate
    maxsize 100M
}

/var/lib/docker/volumes/fiber-maintenance-agent_agent_logs/_data/*.jsonl {
    daily
    rotate 90
    compress
    delaycompress
    missingok
    notifempty
    copytruncate
    maxsize 200M
}
EOF

# 手动执行轮转
logrotate -f /etc/logrotate.d/fiber-agent
```

### 2.4 日志清理

```bash
# 清理 30 天前的日志
docker compose exec deerflow find /var/log/fiber-agent/ -name "*.log" -mtime +30 -delete
docker compose exec deerflow find /var/log/fiber-agent/ -name "*.jsonl" -mtime +90 -delete

# 清理 Docker 未使用日志
docker system prune -f
```

## 3. 备份与恢复

### 3.1 备份对象

| 数据       | 路径                    | 重要性 | 备份频率           |
| ---------- | ----------------------- | ------ | ------------------ |
| 知识库文档 | `knowledge_base/`     | 🔴 高  | 每日               |
| 向量数据库 | `data/chroma/`        | 🔴 高  | 每日               |
| 记忆数据库 | `data/memory.db`      | 🟡 中  | 每日               |
| 配置文件   | `config.yaml`         | 🔴 高  | 变更时             |
| 插件       | `plugins/`            | 🟡 中  | 变更时             |
| Skills     | `skills/`             | 🟡 中  | 变更时             |
| 报告文件   | `data/fiber_reports/` | 🟢 低  | 不备份（24h 过期） |

### 3.2 备份脚本

**`scripts/backup.sh`**：

```bash
#!/bin/bash
# 光纤维护系统 每日备份脚本
set -euo pipefail

BACKUP_DIR="/opt/backups/fiber-agent"
TIMESTAMP=$(date +%Y%m%d_%H%M%S)
BACKUP_PATH="${BACKUP_DIR}/${TIMESTAMP}"
RETENTION_DAYS=30

mkdir -p "$BACKUP_PATH"

echo "[$(date)] 开始备份..."

# 1. 知识库文档
echo "  备份知识库..."
tar czf "${BACKUP_PATH}/knowledge_base.tar.gz" -C "$(pwd)" knowledge_base/

# 2. 向量数据库（需先停止写入或热拷贝）
echo "  备份 ChromaDB..."
docker compose exec deerflow tar czf /tmp/chroma_backup.tar.gz -C /app/data chroma/
docker cp "$(docker compose ps -q deerflow):/tmp/chroma_backup.tar.gz" "${BACKUP_PATH}/"
docker compose exec deerflow rm -f /tmp/chroma_backup.tar.gz

# 3. 记忆数据库
echo "  备份 Memory DB..."
docker compose exec deerflow cp /app/data/memory.db /tmp/memory_backup.db
docker cp "$(docker compose ps -q deerflow):/tmp/memory_backup.db" "${BACKUP_PATH}/memory.db"
docker compose exec deerflow rm -f /tmp/memory_backup.db

# 4. 配置 + 插件 + Skills
echo "  备份配置..."
tar czf "${BACKUP_PATH}/config.tar.gz" config.yaml plugins/ skills/

# 5. 清理过期备份
echo "  清理 ${RETENTION_DAYS} 天前的备份..."
find "$BACKUP_DIR" -maxdepth 1 -type d -mtime +${RETENTION_DAYS} -exec rm -rf {} + 2>/dev/null || true

echo "[$(date)] 备份完成: ${BACKUP_PATH}"
du -sh "$BACKUP_PATH"
```

### 3.3 恢复流程

```bash
# 1. 停止服务
docker compose down

# 2. 恢复知识库
tar xzf /opt/backups/fiber-agent/20260721_020000/knowledge_base.tar.gz -C .

# 3. 恢复 ChromaDB
docker compose up -d deerflow
docker cp /opt/backups/fiber-agent/20260721_020000/chroma_backup.tar.gz \
    "$(docker compose ps -q deerflow):/tmp/"
docker compose exec deerflow bash -c "cd /app/data && tar xzf /tmp/chroma_backup.tar.gz"

# 4. 恢复 Memory DB
docker cp /opt/backups/fiber-agent/20260721_020000/memory.db \
    "$(docker compose ps -q deerflow):/app/data/memory.db"

# 5. 重建知识库索引（如 ChromaDB 损坏）
docker compose exec deerflow python -m src.rag.ingest --rebuild

# 6. 重启
docker compose restart deerflow
```

### 3.4 定时备份（Crontab）

```bash
# 每日凌晨 2:00 执行备份
crontab -e
0 2 * * * /opt/fiber-maintenance-agent/scripts/backup.sh >> /var/log/fiber-backup.log 2>&1
```

## 4. 扩缩容

### 4.1 水平扩展（多实例）

```yaml
# docker-compose.override.yaml
services:
  deerflow:
    deploy:
      replicas: 3
    # 注意：多实例需共享 ChromaDB 和 Memory DB
    # 建议将 ChromaDB 改为独立服务模式
```

```bash
# 扩展到 3 个 Agent 实例
docker compose up -d --scale deerflow=3

# 缩回 1 个
docker compose up -d --scale deerflow=1
```

> ⚠️ **注意**：多实例部署时，`data/memory.db`（SQLite）不支持并发写入，需替换为 PostgreSQL。`data/chroma/` 需改为 ChromaDB Server 模式。

### 4.2 垂直扩展（资源调整）

```yaml
# docker-compose.yaml 中修改
services:
  deerflow:
    deploy:
      resources:
        limits:
          cpus: '4.0'
          memory: 8G
        reservations:
          cpus: '2.0'
          memory: 4G

  ollama:
    deploy:
      resources:
        limits:
          memory: 16G
        reservations:
          devices:
            - driver: nvidia
              count: all
              capabilities: [gpu]
```

```bash
# 应用资源变更
docker compose up -d
```

### 4.3 Sub-Agent 并发调整

```yaml
# config.yaml
agents:
  subagents:
    max_concurrent: 10    # 从 5 调整为 10（需后端支撑）
    task_timeout_seconds: 20
```

```yaml

llm:
  profiles:
    primary:  { temperature: 0.3, max_tokens: 4096 }   # 正常
```

### 7.3 告警规则配置

**`monitoring/alert_rules.yml`**：

```yaml
groups:
  - name: fiber-agent-alerts
    rules:
      # 后端不可用
      - alert: BackendDown
        expr: backend_up == 0
        for: 1m
        labels:
          severity: critical
        annotations:
          summary: "光纤后端服务不可用"
          description: "API Gateway 已离线超过 1 分钟"

      # Agent 错误率过高
      - alert: HighErrorRate
        expr: rate(agent_request_total{status="error"}[5m]) / rate(agent_request_total[5m]) > 0.1
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "Agent 错误率超过 10%"

      # 模型熔断
      - alert: ModelCircuitOpen
        expr: increase(agent_model_degradation_total{level="circuit_open"}[5m]) > 0
        labels:
          severity: critical
        annotations:
          summary: "LLM 模型已熔断"

      # 磁盘空间不足
      - alert: DiskSpaceLow
        expr: node_filesystem_avail_bytes{mountpoint="/"} < 5368709120
        labels:
          severity: warning
        annotations:
          summary: "磁盘剩余空间不足 5GB"
```

## 8. 故障排查手册

### 8.1 故障决策树

```
服务异常
├── Agent 无响应？
│   ├── docker compose ps → 是否 Up？
│   │   ├── 否 → docker compose logs deerflow → 查看启动错误
│   │   └── 是 → curl /api/v1/health → 是否 200？
│   │       ├── 否 → 查看 app.log 最近错误
│   │       └── 是 → 检查网络/防火墙/端口映射
│   └── OOM？→ docker inspect deerflow | grep -i oom
│
├── LLM 回复异常？
│   ├── 模型熔断？→ 查看日志 "模型熔断" 关键字
│   │   └── 等待 60s 自动恢复 / 重启 ollama
│   ├── 回复质量差？→ 检查降级级别
│   │   └── grep "模型降级" /var/log/fiber-agent/app.log
│   └── 超时？→ 检查 GPU 利用率
│       └── nvidia-smi / docker stats ollama
│
├── 后端数据异常？
│   ├── MCP 调用失败？→ 查看 mcp.jsonl 审计日志
│   │   └── grep "连接失败" mcp.jsonl
│   ├── 离线模式？→ curl /api/v1/health → offline_mode
│   │   └── 检查 fiber-backend 服务状态
│   └── 数据不一致？→ 对比 REST 轮询 vs WS 推送
│
├── RAG 检索无结果？
│   ├── ChromaDB 正常？→ curl :8100/api/v1/heartbeat
│   ├── 知识库已入库？→ 查看 ACTIVE 文档数
│   │   └── curl /api/v1/knowledge/docs?status=ACTIVE
│   └── 重建索引 → python -m src.rag.ingest --rebuild
│
└── 前端页面异常？
    ├── WS 断开？→ 检查 nginx.conf proxy_pass
    ├── API 404？→ 检查 nginx /api/ 代理配置
    └── 白屏？→ 浏览器 F12 查看控制台错误
```

### 8.2 常见故障速查

| 故障现象                            | 可能原因                    | 解决方案                                              |
| ----------------------------------- | --------------------------- | ----------------------------------------------------- |
| Agent 启动报`ModuleNotFoundError` | 依赖未安装                  | `docker compose build --no-cache deerflow`          |
| Ollama 响应极慢                     | GPU 显存不足 / 模型过大     | 换小模型`qwen2.5:7b` 或增加显存                     |
| ChromaDB 连接拒绝                   | 容器未启动 / 端口冲突       | `docker compose restart chromadb`                   |
| 前端 WS 频繁断连                    | Nginx 超时 / 后端 WS 崩溃   | 检查`proxy_read_timeout`；重启后端                  |
| 报告下载 404                        | 文件已过期（24h）           | 重新生成报告                                          |
| 知识库检索无结果                    | 未入库 / Embedding 模型缺失 | 执行`--rebuild`；检查 `bge-large-zh`              |
| 模型熔断不恢复                      | Ollama 进程挂死             | `docker compose restart ollama`                     |
| 磁盘空间不足                        | 日志/模型/向量数据膨胀      | 清理日志 + 删除旧模型 +`docker system prune`        |
| 批量分析超时                        | 后端响应慢 / 并发过高       | 调大`task_timeout_seconds`；降低 `max_concurrent` |
| 企业微信通知失败                    | Webhook URL 过期            | 重新生成 Webhook；检查网络出口                        |

### 8.3 紧急恢复操作

```bash
# 场景 1：Agent 完全无响应
docker compose restart deerflow
sleep 5
curl http://localhost:8000/api/v1/health

# 场景 2：LLM 完全不可用
docker compose restart ollama
sleep 10
docker compose exec ollama ollama list
docker compose restart deerflow

# 场景 3：ChromaDB 数据损坏
docker compose down
rm -rf data/chroma/
docker compose up -d
docker compose exec deerflow python -m src.rag.ingest --rebuild

docker compose down

docker compose up -d --build
```

## 10. 安全加固

### 10.1 网络隔离

```yaml
# docker-compose.yaml — 内部网络
networks:
  internal:
    driver: bridge
    internal: true    # 不可访问外网
  external:
    driver: bridge

services:
  deerflow:
    networks: [internal, external]
  fiber-backend:
    networks: [internal]    # 后端不暴露外网
  ollama:
    networks: [internal]
  chromadb:
    networks: [internal]
```

### 10.2 端口最小化暴露

```yaml
# 仅暴露必要端口
services:
  frontend:
    ports: ["5173:5173"]    # 前端（唯一对外入口）
  deerflow:
    ports: ["8000:8000"]    # Agent API（可选，前端已代理）
  grafana:
    ports: ["127.0.0.1:3001:3000"]   # 仅本机访问
  prometheus:
    ports: ["127.0.0.1:9090:9090"]   # 仅本机访问
```

### 10.3 敏感信息保护

```bash
# 使用 .env 文件管理密钥（不提交 Git）
cat > .env << 'EOF'
WECOM_WEBHOOK=https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx
SMTP_HOST=smtp.example.com
SMTP_USER=alert@example.com
SMTP_PASS=your_password
EOF

# .gitignore 中排除
echo ".env" >> .gitignore
```

### 10.4 API 访问控制

```bash
# 知识库管理接口需 admin 角色
# 通过 X-User-Role 头控制（生产环境应接入统一认证）
curl -H "X-User-Role: admin" http://localhost:8000/api/v1/knowledge/docs
```

### 10.5 容器安全

```bash
# 非 root 运行（Dockerfile.agent 中添加）
RUN useradd -m appuser
USER appuser

# 只读文件系统（docker-compose.yaml）
services:
  deerflow:
    read_only: true
    tmpfs:
      - /tmp
    volumes:
      - agent_data:/app/data
      - agent_logs:/var/log/fiber-agent
```
